## Problem vi stötte på

### 1. Authentication Loop
**Symptom:** Alla anrop till `/api/migrate-my-data` returnerar 401 "Ogiltig session"

**Orsak:**

- Användaren måste logga in igen för att få ny token
- Men migration tar för lång tid → token hinner gå ut innan den slutförs

**Försökt:**
- Logga ut/in igen → token går ut ändå
- Browser console metod → samma problem

## Nästa steg (rekommendationer)

### Alt 1: Fix auth token expiry (RECOMMENDED)
**Implementera refresh token logic:**
1. I `/api/migrate-my-data` endpoint: kolla token expiry
2. Om token snart går ut → använd refresh_token för att få ny access_token
3. Fortsätt migration med fresh token

**Filer att ändra:**
- `v2/api/index.py` line ~1788 (POST /api/migrate-my-data)

### Alt 2: Använd service role key
**Security trade-off:**
- Användaren behöver ge service_role_key EN GÅNG
- Claude Code kan köra migration direkt via Python här
- Uppdatera `migrate_user_data.py` med full data från index.py
- Kör: `python v2/migrate_user_data.py`

**Filer att uppdatera:**
- `v2/migrate_user_data.py` (ersätt all data med data från index.py lines 1806-2700)

### Alt 3: Gör migration mer granular
**Split migration i flera steg:**
- Steg 1: Migrera PROFILE (snabbt)
- Steg 2: Migrera EXPERIENCES (10 i taget)
- Steg 3: Migrera SKILLS
- Steg 4: Migrera CV_VERSIONS
- etc.

Detta minskar risken för timeout/token expiry

### Alt 4: Använd Supabase client-side insert
**Från browser console:**
```javascript
const { data, error } = await supabase
  .from('user_experiences')
  .insert([...EXPERIENCES])
```

Men detta kräver att user har insert permissions och att vi kopierar all data till console
